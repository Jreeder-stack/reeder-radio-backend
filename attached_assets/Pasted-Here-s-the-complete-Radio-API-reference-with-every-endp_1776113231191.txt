Here's the complete Radio API reference with every endpoint, request body, and response format:

Authentication
All endpoints require:

Header: x-api-key: <RADIO_API_KEY>

Error responses always follow:

{ "error": "Error message" }

1. UNIT STATUS MANAGEMENT
POST /api/radio/status — Update unit status
Request:

{
  "unit_id": "INDIANA-1",
  "status": "on duty",
  "timestamp": "1423",
  "channel": "OPS1"
}

Required: unit_id, status
Valid statuses: on duty, off duty, busy, en route, on scene, available, assign, court, training, out of service, unavailable, special duty, not available, out of vehicle, detail

Response:

{
  "success": true,
  "unit_id": "INDIANA-1",
  "status": "on_duty",
  "timestamp": "1423",
  "channel": "OPS1"
}

POST /api/radio/unit/:unitId/status/cycle — Single-button status cycle
Cycles automatically:

Without active call: off_duty ↔ on_duty
With active call: on_duty → en_route → on_scene → on_duty
Request: (no body required, unitId is in the URL)

Response:

{
  "success": true,
  "unitId": "INDIANA-1",
  "previousStatus": "on_duty",
  "newStatus": "en_route",
  "hasActiveCall": true,
  "callId": "uuid-here",
  "callNumber": "041325-143022",
  "timestamp": "2026-04-13T14:30:22.000Z"
}

2. CALL MANAGEMENT

Request:

  "location": "123 Main St",
  "city": "Springfield",

  "call_number": "041325-143022",

POST /api/radio/clear — Clear unit from call
Request:

{
  "unit_id": "INDIANA-1",
  "call_id": "uuid-here"
}

Required: unit_id. call_id is optional (if omitted, just sets status to available).

Response:

{
  "success": true,
  "unit_id": "INDIANA-1",
  "status": "available",
  "cleared_from_call": "uuid-here"
}
