## Findings that affect implementation

The managed runtime receives signaling events but forwards only channel/unit identifiers and legacy positional values. V3 creates a correlation ID at capture start, yet has no immutable turn envelope, intake sequence or runtime-generation record. Speech capture retains a start timestamp internally and drops it from returned transmissions. Scheduling occurs after STT completion; changing that scheduling is 01-03, not a completion claim for 01-02.

Credential verification and canonical callsign lookup must remain distinct. The Socket.IO authentication path can resolve a claimed login when no session cookie was verified; that lookup must not mint an authenticated AI actor. The radio-token path proves a device, but needs its successfully resolved, enabled assigned account before it can prove a CAD speaker. The HTTP PTT path's presence check is not proof of ownership by the current request. The authenticated notify-PTT endpoint is another intake path through two compatibility forwarding layers.

Existing server-owned channel grants are available in `user_channel_access` joined to enabled `channels`. Read them using the authenticated account ID, not a client-supplied callsign, dispatcher flag or current presence. The available evidence chain is account credentials, account channel grants, an unambiguous configured channel-to-center mapping, then authoritative speaker resolution in that center. The tracked schema does not establish a separate account-to-CAD-center foreign key. A bare channel name, or simply finding one runtime for a client-selected channel, does not establish permission.

## Proposed coordinated implementation

Use one shared internal provenance issuer/checker module. Mint deeply frozen, module-tagged principals only after real stored-session or radio-token verification, with account, connection, canonical unit and server-read channel grants. Plain JSON objects from requests cannot become trusted by setting a boolean. Do not copy cookies, session credentials or radio tokens into envelopes or logs. An opaque server-issued session connection handle can use existing session JSON without a schema change.

Create server-owned transmission metadata at accepted PTT start. Carry the same metadata through normal end, drain finalization and forced end. Keep it out of public transport payloads; internal callback metadata or non-enumerable/private associations preserve wire compatibility. Preserve metadata through both compatibility services and the runtime manager.

At V3 intake, allocate a unique turn ID and monotonic intake sequence before asynchronous work, with runtime generation, selected center/channel, authenticated connection and speaker, capture start/end times and transmission ID. Keep the requested target in action input. A spoken callsign or model output cannot replace the speaker. Require trusted source evidence and center-scoped speaker resolution before transcript-triggered mutation, preserving existing action scopes and hardware-emergency policy.

Carry the envelope through speech capture/transcription, planning, materialization/execution, response/output and diagnostics, including empty/error terminal paths. Deduplicate repeated internal events by transmission identity with bounded retention. Do not label sequence recording as repaired execution ordering, or generation recording as complete cancellation/freshness enforcement.

## Required tests and compatibility limit

Test ordered intake numbering while STT finishes in reverse order; unchanged envelope identity at every stage; duplicate start/end; an old drained end versus a new capture; same callsigns across connections/centers; session and assigned-radio positives; missing/ambiguous/unverified sources; actor-resolution failure with a resolvable explicit target; spoken target versus authenticated actor; existing scope rejection; all compatibility entry points; generation uniqueness after restart; and unchanged healthy hardware-emergency behavior.

Legacy wire events without request/transmission IDs cannot distinguish every delayed same-connection end from a legitimate end of a newer capture. They also cannot distinguish every replayed start after completion from a new physical transmission. Server-generated IDs solve correlated internal-event duplication and preserve captured drain identity; they do not create evidence absent from a legacy packet. Document that limit and fail closed when ownership is ambiguous. Do not introduce a mandatory client-protocol or firmware change under this item.
