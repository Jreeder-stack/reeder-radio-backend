## Original defect, repairs and safety properties
The old `src/dispatcher-v3/diagnostics.js` journal stored and logged complete event objects, including `transcript`, planner data, nested CAD request/result payloads and strings that could contain privileged information. `getRecent()` returned those entries without a required diagnostic reader scope. Although it capped stored entries at 500, it had no time-based expiry, keyed event-storm suppression or structured operator-friendly cause classification.

The replacement journal in `src/dispatcher-v3/diagnostics.js` provides:
- A default **500-entry journal**, **15-minute in-memory retention**, maximum configurable clamp of 1,000 entries and 1 hour, and bounded keyed rate bookkeeping. Repeated nonterminal events are limited to **12 per phase+turn per 1,000ms** by default; the console emits one structural marker rather than repeatedly dumping events. Unique terminal callbacks remain visible, while duplicate console messages are suppressed.
- An allowlisted, size-capped **sanitized details** object. It excludes full transcripts, free-form radio text, notes, location/address, model prompts/plans, CAD bodies/results, headers, credential material and raw PCM. It retains bounded structural reason/error codes, count/duration metrics and numeric provider token usage. Safe nested error codes are extracted into `details.code`, not whole error objects.
- Correlation IDs and original trusted turn identity retained internally for testable phase lineage; **operator reads omit the original turn envelope and identity** and require an explicit same-center/same-runtime `dispatcher.diagnostics.read` or `dispatcher.admin` access scope. No new HTTP operator endpoint is exposed; a future caller MUST derive the access context from authenticated server state rather than client-provided JSON. End-to-end production UI access checks remain unverified. `getPipelineStatus()` now exposes only aggregate diagnostics, not raw recent records.
- Typed outcome categories: `not_addressed`, `unintelligible_audio`, `ambiguity`, `unsupported_capability`, `denied_action`, `provider_failure`, `delivery_failure`, `expired_or_canceled`, `action_failure`, and success/progress categories. The accepted turn is tracked from trusted intake through its terminal `turn_scheduler_terminal` / `turn_completed` or stopped capture.
- Tenant-filtered `getSummary()` counts, including scoped suppression totals, to avoid mixing two dispatch centers if they use a shared journal. `getTrace()` filters by true turn ID and center-scoped access. The bounded journal is ephemeral and not a database/audit log persistence system.

Instrumentation connects the existing STT and planner timing, addressing gate (`turn_addressed`), conversation selection, action/executor outcome, CAD header+body request timing (`cad_request_started/completed/failed`), read-back verification when explicitly available (`cad_verification_outcome`), 01-03 queue age and total age, 01-06 outbound radio completion/interruption/expiry and lifecycle terminal outcome. Provider token usage is recorded when reported by the model SDK. **USD cost is not invented** because no approved tariff is present. Radio `outbound_completed` means audio injected into the relay, not a confirmed distant device receipt.

No changes were made to transport, codec, radio firmware, CAD schema, providers, voice emergency policy, security scopes for CAD mutations or the CREATE_CALL verification requirement. The production read-access route is intentionally not added without a separate verified server-auth design.
