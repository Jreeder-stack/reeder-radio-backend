## Root cause and scope
01-02 preserved generation and authenticated identity in a frozen envelope, but a stopped/restarted runtime did not revalidate generation at async boundaries before downstream effects. 01-03 queues and 01-04 deadlines covered certain stale outcomes but were not themselves full task-ownership or credential-revocation guards. A pending clarification could expire or be superseded during a model call. An already submitted CAD write must be distinguished from a request not yet sent.

The production path now uses a **private 01-05 lifecycle**, keyed by trusted server-issued turn ID and generation, with an AbortSignal and explicit terminal state. Entry is reserved at trusted intake; the same lifecycle is carried through STT, model/operational context, action execution, CAD request and radio output. Every stage validates current generation and non-cancellation before it can proceed. `stop()` invalidates prior-generation lifecycle states before releasing resources; restarting creates a different generation. Life and deadline guards reject stale completions.

The conversation gate identifies the **same pending object and owner** when an unaddressed reply is accepted. That binding is revalidated after asynchronous work and before CAD side effects, so expired/replaced replies cannot mutate the previous task. After safe processing the consumed binding is released **before outbound speech** so legitimate immediate clarifications continue to work.

Each V3 action checks the active runtime CAD scopes (existing contract validation) and a fresh actor/channel grant. The credential is reverified using private, nonserialized proof held only inside `pttProvenance.js`: current non-expired session (matching account ID) or non-locked assigned radio token, current active account, unchanged unit identity and enabled channel grant. This is not derived from spoken callsigns, client payloads, or model output. CAD mutation requests recheck actor permissions immediately before submission, and enforce a synchronous lifecycle check at the actual fetch boundary. Existing CAD read-back verification remains required.

Internal `cancelTurnById` targets **one exact trusted turn ID**, not all queued turns of a callsign. Unsent tasks return `not_submitted`; submitted CAD writes conservatively return `submitted_reconciliation_required` and `possibleUnconfirmedWrite` rather than claiming rollback. Remote operations already sent cannot be undone by client cancellation. No new public cancellation route is exposed without a separate authorization design. Eventual remote-write reconciliation and truthful uncertainty management remain **03-06**. Natural-language cancellation of old field-incident notes (audit R05) remains assigned to its original future conversation-management work; do not credit that repair under 01-05.
